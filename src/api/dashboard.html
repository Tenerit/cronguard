démarrage rapide

          
Ajoutez un ping à la fin de votre script cron. C'est tout. Si le script ne ping pas dans sa fenêtre de grâce, CronGuard vous alerte.


          
1. Créez un service

          
2. Ajoutez le ping à votre script

          

            

              
bash Script shell

              
Une ligne après votre commande. Capture exit_code et logs automatiquement.

            

            

              
node Script Node.js

              
Wrapper async — mesure la durée, capture les erreurs, envoie le ping.

            

          


          
#!/bin/bash
# Votre script existant
./backup.sh
STATUS=$?
LOG=$(cat /var/log/backup.log 2>/dev/null | tail -50)

# Ping CronGuard (remplacez VOTRE_PING_KEY)
curl -sX POST http://localhost:3000/ping/VOTRE_PING_KEY \
  -H "Content-Type: application/json" \
  -d "{"status":"$([ $STATUS -eq 0 ] && echo success || echo fail)","exit_code":$STATUS,"output":"$LOG"}"



          
// Node.js / TypeScript
const PING_KEY = 'VOTRE_PING_KEY'
const BASE_URL = 'http://localhost:3000'

async function withMonitor(fn) {
  const start = Date.now()
  try {
    const records = await fn()
    await fetch(`${BASE_URL}/ping/${PING_KEY}`, {
      method: 'POST', headers: {'Content-Type':'application/json'},
      body: JSON.stringify({ status: 'success', duration_ms: Date.now()-start, records })
    })
  } catch(err) {
    await fetch(`${BASE_URL}/ping/${PING_KEY}`, {
      method: 'POST', headers: {'Content-Type':'application/json'},
      body: JSON.stringify({ status: 'fail', output: err.message, exit_code: 1 })
    })
    throw err
  }
}

// Utilisation
await withMonitor(async () => {
  const count = await syncDatabase()
  return count // nombre d'enregistrements traités
})



          
import requests, time, traceback

PING_KEY = 'VOTRE_PING_KEY'
BASE_URL = 'http://localhost:3000'

def with_monitor(fn):
    start = time.time()
    try:
        records = fn()
        requests.post(f'{BASE_URL}/ping/{PING_KEY}', json={
            'status': 'success',
            'duration_ms': int((time.time()-start)*1000),
            'records': records
        })
    except Exception as e:
        requests.post(f'{BASE_URL}/ping/{PING_KEY}', json={
            'status': 'fail',
            'output': traceback.format_exc()[-3000:],
            'exit_code': 1
        })
        raise

# Utilisation
with_monitor(lambda: sync_database())


        


        

          
payload du ping

          
Tous les champs sont optionnels sauf status.

          
{
  "status":      "success" | "fail",    // obligatoire
  "duration_ms": 4521,                  // durée en ms (pour détection d'anomalie)
  "records":     15230,                 // nb d'enregistrements (pour output validation)
  "exit_code":   0,                     // code de retour du script
  "output":      "logs du script..."   // envoyé au LLM si status=fail (max 4000c)
}



          
validation de sortie

          
Si vous configurez records min/max sur un service, CronGuard reclasse automatiquement un ping « success » avec 0 record en « fail ». Idéal pour détecter les backups silencieux qui ne traitent rien.

        


        

          
détection d'anomalies

          

            

              
Timeout (silence)

              
Si votre script ne ping pas dans la fenêtre de grâce (configurable), CronGuard détecte l'absence et alerte.

            

            

              
Dérive de performance

              
Si un job prend ×2.5 sa durée de référence (7 jours), une alerte est émise avant le timeout.

            

            

              
Validation de sortie

              
Exit 0 mais 0 enregistrement traité ? CronGuard reclasse en échec.

            

            

              
Analyse IA

              
Le LLM analyse les logs localement. Vos données ne quittent jamais votre serveur.

POST /monitors/:id/pause          # Pause temporaire
POST /monitors/:id/resume         # Reprend après pause

POST /monitors/:id/snooze         # Snooze N minutes
POST /monitors/:id/test           # Envoie une alerte de test

GET  /dashboard/logs              # Journal d'activité
GET  /dashboard/analyses          # Dernières analyses IA
GET  /clients/me                  # Profil compte
PATCH /clients/settings           # Paramètres (Slack, etc.)
GET  /status/:monitor_id          # Page de statut publique
GET  /health                      # Santé de l'API

# Toutes les routes nécessitent : X-API-Key: votre_cle
